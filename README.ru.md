# Decky Controller

Плагин для [Decky Loader](https://decky.xyz), который превращает Steam Deck в USB‑геймпад для другого ПК —
прямо из игрового режима. Подключите Deck к ПК кабелем USB‑C, включите **Controller mode** в меню быстрого
доступа — и ПК увидит обычный USB‑геймпад: **XInput** (работает в Windows «из коробки») или **generic HID**;
другие профили в планах. Пока Deck работает контроллером, его экран выключен; чтобы вернуть Deck себе,
удерживайте комбинацию выхода (по умолчанию **L4+R4**, настраивается). Без Desktop Mode, без пароля, без
установки чего‑либо на ПК.

Всё происходит в памяти: системные файлы не изменяются, перезагрузка всегда возвращает Deck в обычное состояние.

## Требования

* Steam Deck с SteamOS 3.6 или новее и Decky Loader.
* Включённый в BIOS режим USB Dual‑Role Device (DRD) — один раз, шаги ниже.
* **Дата‑кабель** USB‑C до ПК (многие кабели только для зарядки не имеют линий данных — если ПК так и не
  видит Deck, попробуйте другой кабель).

### Включение DRD в BIOS (один раз)

По умолчанию порт USB‑C у Deck работает только как хост (для док‑станций и периферии). Dual‑Role позволяет
порту также быть устройством, когда он подключён к компьютеру. При включённом DRD порт по‑прежнему работает
как хост, когда подключена док‑станция или периферия — роль определяется тем, что воткнуто.

1. Полностью **выключите** Deck.
2. Удерживая **Volume Up**, нажмите **Power**; отпустите обе кнопки, когда услышите звуковой сигнал —
   откроется меню BIOS.
3. Выберите **Setup Utility**.
4. Перейдите в **Advanced → USB Configuration → USB Dual‑Role Device**.
5. Измените значение с **XHCI** на **DRD**.
6. Сохраните и выйдите (**Exit → Exit Saving Changes** или F10). Deck перезагрузится.

Кнопка **How to enable DRD** в плагине показывает те же шаги прямо на Deck. Примечание: при включённом DRD
**Windows, установленная на Deck**, теряет USB‑порт (у Windows нет драйвера для dual‑role‑контроллера).
Если вам нужен USB в Windows‑на‑Deck — верните XHCI; SteamOS работает в любом режиме.

## Установка

1. Скачайте `decky-controller.zip` из GitHub Releases:
   <https://github.com/flexlug/decky-controller/releases/latest/download/decky-controller.zip>
2. На Deck: **Decky → Settings → Developer mode** → включить.
3. **Decky → Developer → Install Plugin from URL** и вставьте ссылку выше — или **Install Plugin from ZIP**,
   если вы скопировали zip на Deck (SD‑карта, флешка, …).
4. **Decky Controller** появится в меню быстрого доступа (вкладка Decky).

Release‑zip — пока единственный канал распространения: плагина нет ни в официальном магазине Decky, ни в
сторонних магазинах.

### Почему плагина нет в официальном магазине Decky?

Чек‑лист подачи в официальную базу плагинов требует, чтобы бо́льшая часть кода не была написана генеративным
ИИ. Этот плагин написан с помощью ИИ‑агентов (с ревью и тестированием человеком на реальном железе), поэтому
подаваться туда не будет. Он распространяется через GitHub Releases / установку по URL, при этом соблюдая
остальные технические требования магазина.

## Использование

1. Подключите Deck к ПК дата‑кабелем USB‑C (отключите док‑станцию — порт может делать только одно дело
   одновременно).
2. Откройте меню быстрого доступа (кнопка …) → **Decky Controller**. В секции **Status** показаны **DRD**,
   **Cable** (что порт видит в простое: **PC**, **Charger**, **Dock**, **Not connected**, **Unknown**),
   **Controller** и **Mode**. Когда режим контроллера включён, строка кабеля становится **Host** и показывает
   **Waiting…**, пока ПК не опознает контроллер, затем **Connected**.
3. Включите **Controller mode**. Встроенный контроллер Deck перехватывается, экран гаснет, и ПК видит новый
   контроллер в течение пары секунд. Для проверки подойдёт `joy.cpl` в Windows или любая игра.
4. Играйте. Чтобы остановиться: удерживайте комбинацию выхода (по умолчанию **L4+R4**, 1,5 с), либо коснитесь
   экрана (он проснётся на несколько секунд) и нажмите **Stop (full reset)**, либо отключите кабель. Экран
   вернётся, Steam снова увидит контроллер.

Пока режим контроллера активен, сам Deck не реагирует ни на какой ввод — включая кнопки Steam и QAM, — потому
что каждый отчёт уходит на ПК. Так и задумано.

### Профили

| Профиль | Что видит ПК | Для чего |
|---|---|---|
| **XInput** (совместим с Xbox 360) — по умолчанию | проводной XInput‑контроллер (VID 045E / PID 028E), обрабатывается встроенным в Windows `xusb22.sys`; в Linux — `xpad` | игры под Windows в Steam и вне его, эмуляторы, всё, что работает с XInput |
| **Generic HID** | стандартный USB HID‑геймпад (6 осей, hat, 16 кнопок) | Linux‑хосты, софт только с DirectInput, запасной вариант |

Раскладка по умолчанию (XInput): A/B/X/Y → A/B/X/Y, L1/R1 → LB/RB, L2/R2 → триггеры, стики → стики, L3/R3,
View → Back, Menu → Start, D‑pad → D‑pad. Steam и QAM **не** передаются. Четыре задние кнопки (L4/L5/R4/R5)
можно назначить на любую кнопку в секции **Back paddles**; комбинация выхода на ПК никогда не отправляется.

### Настройки

* **Profile** — XInput (Xbox 360) / Generic HID.
* **Kill switch** (комбинация выхода) — L4+R4, L5+R5, L4+L5+R4+R5 или Steam+QAM, удержание 1,5 с. Время
  удержания в панели не настраивается; при необходимости измените `kill_hold_ms` в
  `~/homebrew/settings/decky-controller/settings.json`.
* **Turn screen off while active** — экономит батарею и скрывает «замороженный» интерфейс; касание экрана
  будит его на несколько секунд, чтобы дотянуться до **Stop**. В игровом режиме панель действительно
  выключается (сон дисплея gamescope); в Desktop Mode используется KDE DPMS, если доступен, иначе только
  гасится подсветка.
* **Back paddles** — что L4/L5/R4/R5 отправляют на ПК (A/B/X/Y, LB/RB, L3/R3, View/Menu, D‑pad или ничего).

## Ограничения

* Порт USB‑C — *либо* хост‑порт, *либо* канал контроллера. Док‑станции, хабы, Ethernet‑адаптеры и другие
  USB‑устройства нельзя использовать, пока включён режим контроллера (подключение такого устройства снова
  делает порт хостом). Зарядка через USB‑порт ПК ограничена тем, что этот порт отдаёт.
* Интерфейс Deck полностью заблокирован, пока режим активен (включая кнопку Steam) — так и задумано.
* Гироскоп, трекпады, вибрация и вывод по Bluetooth в этой версии не поддерживаются.
* У Windows, установленной **на Deck**, нет USB при включённом DRD (см. выше).

## Решение проблем

* **DRD: not detected / «DRD not enabled»** → выполните шаги в BIOS выше; после включения панель покажет DRD
  on сразу после загрузки SteamOS.
* **Cable: Not connected**, хотя кабель вставлен → порт вообще не видит питания: кабель или порт неисправен,
  либо порт ПК спит. Попробуйте другой кабель (обязательно с линиями данных) или порт; некоторым ПК нужна
  секунда после подключения. **Charger** → это зарядное устройство, а не ПК. **Dock** → отключите
  док‑станцию/аксессуар. **Unknown** → показания ещё недоступны; откройте панель заново через секунду.
* **Режим контроллера не запускается / ПК ничего не видит** → нажмите **Stop (full reset)**, переподключите
  кабель, попробуйте снова.
* **Собственный контроллер Deck не работает после сбоя** → нажмите **Stop (full reset)** (сенсорный экран
  работает всегда) или просто перезагрузитесь: все изменения живут в памяти ядра и исчезают при перезагрузке.
* **Логи**: **Decky → Settings → Developer → Show plugin logs**, либо файлы в
  `~/homebrew/logs/decky-controller/` (`~/homebrew` — домашний каталог Decky Loader на Deck). Кнопка
  **Diagnostics** в панели включает последние 50 строк демона.

## Безопасность

Плагин меняет только энергозависимое состояние ядра: на время работы отвязывает встроенный контроллер от
драйвера `usbhid`, создаёт USB‑гаджет на порту USB‑C через интерфейсы ядра `raw_gadget` / `configfs` и
усыпляет дисплей (gamescope / KDE DPMS либо гасит подсветку). Ничего не записывается в корневую файловую
систему (только для чтения), загрузчик, EFI‑раздел или BIOS. Единственная постоянная настройка —
переключатель DRD в BIOS, который вы меняете сами. Каждый шаг откатывается при завершении сессии, при остановке
или выгрузке плагина и — в худшем случае — перезагрузкой.
